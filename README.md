
# TaskFlow Task-Tracker для фрилансеров

## 1. Назначение системы

Система позволяет фрилансеру делиться ходом работ с заказчиком, скрывая внутреннюю кухню (бэклог, промежуточные задачи, черновики). Заказчик получает ограниченный доступ только к релевантным данным.

---

## 2. Пользователи системы

| Поле | Описание |
| :--- | :--- |
| **ID** | Уникальный идентификатор пользователя |
| **Логин** | Уникальное имя пользователя для входа |
| **Пароль** | Хешированный пароль |
| **Роль** | `OWNER`, `CLIENT` или `TEAM` |
| **Имя** | Отображаемое имя пользователя |
| **Контактные данные** | Email, телефон (опционально) |
| **Стоимость часа (hourly_rate)** | Ставка в валюте (например, `1500 ₽/час` или `$50/час`). Используется для расчёта стоимости проекта. |

| Тип пользователя | Описание |
| :--- | :--- |
| **User** | Владелец аккаунта. Имеет логин, пароль и роль. |
| **Client** | Заказчик. Привязывается к конкретному проекту. Видит только свои проекты. |
| **Owner** | Фрилансер, создавший проект. Является суперпользователем внутри своего проекта. |
| **Team** | Член команды разработки. Может быть назначен исполнителем или ревьювером задач. |

---

## 3. Модель данных (Иерархия)

```
User (владелец аккаунта)
  ├── id
  ├── login / password
  ├── role (OWNER / CLIENT / TEAM)
  ├── name
  ├── contacts
  └── hourly_rate ★ (стоимость часа)
        │
        └── Client (заказчик)
              └── Project (проект)
                    ├── budget (часы)
                    ├── deadline
                    └── Task (задача)
                          ├── title, description
                          ├── status, priority
                          ├── tags
                          ├── assignee, reviewer
                          └── deadline
```

| Сущность | Атрибуты |
| :--- | :--- |
| **User** | ID, логин, пароль, роль, имя, контакты, `hourly_rate` |
| **Client** | Привязывается к User. Имеет имя, контактные данные, привязанные проекты |
| **Project** | Название, бюджет (часы), дедлайн, заказчик, прогресс-бар |
| **Task** | Название (title), описание, статус, приоритет, теги, исполнитель, ревьювер, дедлайн |

---

## 4. Роли и права доступа

| Роль | Доступ к чтению проектов | Создание задач | Назначение людей | Удаление пользователей |
| :--- | :--- | :---: | :---: | :---: |
| **OWNER** (Фрилансер) | Все свои проекты | ✅ Да | ✅ Да | ✅ Да (внутри своей команды) |
| **CLIENT** (Заказчик) | Только свои (активные + выполненные) | ❌ Нет | ❌ Нет | ❌ Нет |
| **TEAM** (Разработчик) | Только где он исполнитель | ✅ Да (если назначен) | ❌ Нет | ❌ Нет |

### Особенности прав

- **OWNER** — обязателен для существования проекта. Без OWNER'а проект не может быть создан.
- **CLIENT** не видит задачи других заказчиков.
- Для **CLIENT** доступен фильтр по тегам (например, показать все задачи с тегом `question`).

---

## 5. Задачи (Task)

### 5.1. Атрибуты задачи

| Поле | Описание |
| :--- | :--- |
| **Title** | Название задачи (обязательно) |
| **Description** | Описание, что нужно сделать |
| **Status** | Статус выполнения (см. п. 5.2) |
| **Priority** | Приоритет: `LOW`, `MEDIUM` (по умолчанию), `HIGH`, `CRITICAL` |
| **Tags** | Множественные теги (например, `question`, `bug`, `feature`) |
| **Assignee** | Исполнитель задачи (ссылка на User) |
| **Reviewer** | Ревьювер задачи (ссылка на User) |
| **Deadline** | Дедлайн задачи |

### 5.2. Статусы задач

| Статус | Описание | Доступен для CLIENT |
| :--- | :--- | :---: |
| **Backlog** | Задача в бэклоге (не запланирована) | ❌ Нет |
| **To Do** | Готова к выполнению | ✅ Да |
| **In Progress** | В работе | ✅ Да |
| **Review** | На ревью | ✅ Да |
| **Done** | Выполнена | ✅ Да |

### 5.3. Фильтрация задач

| Фильтр | Описание |
| :--- | :--- |
| **Мои задачи** | Показывает задачи, где пользователь — исполнитель или ревьювер |
| **Срочные** | Показывает задачи с дедлайном менее 3 дней или просроченные |
| **По тегам** | Фильтр по одному или нескольким тегам |
| **Просроченные** | Показывает все просроченные задачи (включая уже выполненные) |

### 5.4. Визуальные индикаторы задач

| Условие | Индикатор |
| :--- | :--- |
| Дедлайн < 3 дней или просрочена | Задача подсвечивается **красным** |
| Дедлайн < 3 дней | Появляется фильтр/кнопка **«Срочные»** |

---

## 6. Проекты (Project)

### 6.1. Атрибуты проекта

| Поле | Описание |
| :--- | :--- |
| **Название** | Название проекта |
| **Бюджет** | Указывается в часах |
| **Дедлайн** | Дата окончания проекта |
| **Заказчик (Client)** | Ссылка на пользователя с ролью CLIENT |
| **Прогресс-бар** | Рассчитывается как `(Затраченные часы / Итоговые часы) × 100%` |

### 6.2. Расчёт стоимости проекта

| Параметр | Источник | Описание |
| :--- | :--- | :--- |
| **Стоимость часа** | `User.hourly_rate` | Индивидуальная ставка фрилансера (OWNER или TEAM) |
| **Стоимость проекта** | Формула | `Сумма (часы_задачи × hourly_rate_исполнителя)` |

> **Важно:** Стоимость рассчитывается на основе ставки каждого исполнителя, а не единой ставки OWNER'а.

### 6.3. Визуальные индикаторы проектов

| Условие | Индикатор |
| :--- | :--- |
| До дедлайна < 30 дней | Проект подсвечивается **жёлтым** в списках |

---

## 7. Бизнес-правила

| Правило | Описание |
| :--- | :--- |
| **Прогресс проекта** | Прогресс-бар = (Затраченные часы / Итоговые часы) × 100% |
| **Стоимость проекта** | `Сумма (часы_задачи × hourly_rate_исполнителя)` |
| **Теги** | Множественные. CLIENT может фильтровать по ним. |
| **Кнопка «Неудачная оценка»** | Отмечает задачу, где оценка времени была неверной (для последующего пересчёта бюджета/аналитики) |
| **CLIENT доступ** | Только к статусам `To Do`, `In Progress`, `Review`, `Done`. Бэклог скрыт. |
| **hourly_rate** | Хранится в профиле User. Может быть изменён только самим пользователем или OWNER'ом (для TEAM). |

---

## 8. Нефункциональные требования

| Требование | Описание |
| :--- | :--- |
| **Авторизация** | Базовая (логин / пароль) |
| **Дефолтный вход** | `OWNER / OWNER` (суперпользователь) |
| **Роли** | `OWNER`, `CLIENT`, `TEAM` |
